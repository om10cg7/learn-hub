# モバイルナビゲーションのパターン8種（ale.uiux）

- 出典：Instagram @ale.uiux（Ale • UX/UI Design • AI）のリール「Navigation Styles: 8 ways to move around an app」（2026-11-13投稿）
  - https://www.instagram.com/reel/Dfr0Ws7D98x/
  - 全パターンが実際に動くライブ見本で提示される構成。内容は動画解析で確認
  - 関連：ボトムナビの「見た目のスタイル8種」（@vamshi.work）や UI コンポーネント8種（@comunidaduxui）とは別観点。こちらはアプリ全体の移動手段を用途で選ぶカタログ

## 8種

| # | 名称 | 向く場面（動画内の一言定義） |
|---|------|------|
| 1 | Tab bar | 主要セクションへ1タップで届く、基本形 |
| 2 | Drawer | セクションは多いが使用頻度は低いものを収納 |
| 3 | Floating pill | 浮いたピル型バー。スクロール中は隠れる |
| 4 | Top tabs | 1セクション内のビューの切り替え |
| 5 | Bottom sheet | 同じ画面のまま出すクイックアクション |
| 6 | Speed dial | 作成系の入口が多いとき（FAB の展開） |
| 7 | Full-screen menu | ポートフォリオやブランドサイトの演出型 |
| 8 | Command search | パワーユーザー向けの検索コマンド起動 |

## 学び

- 切り分けの軸は「セクション数 × 使用頻度 × 目的」：常時表示の Tab bar、頻度が低いものを隠す Drawer、1画面内の切替は Top tabs、作成の入口は Speed dial、という具合に移動の種類ごとに器が違う
- Bottom sheet が「アクション呼び出し」としてナビゲーションに数えられているのが要点。画面遷移だけでなく、移動を伴わない呼び出しも動線設計の一部として扱う
- Command search はデスクトップのパレット型 UI（⌘K）のモバイル移植で、項目数が多いアプリほど効く。AI に頼むときも「タブバーにして」ではなくパターン名で指定すると意図が通る、名前シリーズ共通の効用
