# Anthropic式「長時間動くエージェントハーネス」の実践構成（状態はファイルに持たせる多モデル分業）

- 日付: 2026-11-17
- 作者: NO1ennn @N01ennn
- カテゴリ: Claude Code
- 元ネタ: https://x.com/N01ennn/status/2122382693732065301

## 要約

X投稿（投稿日時 2026-11-17 02:34 表示）で紹介された、Anthropic の「長時間動くエージェントハーネス」を実践する多モデルの役割分担構成。流れは、Fable 5.2 が advisor として助言し、Sonnet 5.5 が機能を1つずつ実装し、Opus 5.5 がブラウザでテストし、Haiku 5.5 がファイル群を swarm 処理する。区切りごとに git commit と進捗ノートを残し、次のセッションはその成果物から続きを引き継ぐ。

核の考え方は「エージェントはセッションごとに全部忘れる。ファイルは忘れない」で、状態はモデルの文脈ではなくファイルに持たせる。状態の置き場は、進捗ノート claude-progress.txt、機能リスト feature_list.json、git log の3つ。

出典は作者の自己返信で示された2件。Anthropic 公式記事「Effective harnesses for long-running agents」（https://www.anthropic.com/research/effective-harnesses-for-long-running-agents、2025-11-26）は、initializer agent が init.sh／claude-progress.txt／初期コミットを用意し、coding agent が feature list から1機能ずつ進めて、E2E テスト後に commit と進捗ノートを残す方式を解説したもの。もう1件は Claude Code 公式ドキュメントの advisor tool（https://code.claude.com/docs/en/advisor）で、`/advisor` や `claude --advisor opus` で有効化する実験的機能（v2.1.300 以降）。モデル名の「5.5／5.2」という表記は投稿内の作者表記ママ。投稿は作者の過去記事「Claude Fable 5.2 解説」も引用しているが、主題はハーネス構成の方。

なお @HeLi8866 の「Claude Codeで3モデルを分業させる構成」（同日、notes/2026-11-17-2122374395834622408.md）も advisor を使う分業を扱うが、あちらは主会話＋サブエージェント＋顧問という分業一般、本投稿は長時間ハーネスとファイルによる状態保持が主題で角度が異なるため、相互参照のうえ別ノートとして収録した。
