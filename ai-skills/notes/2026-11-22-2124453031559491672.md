# AIエージェントの4層エンジニアリング（Prompt／Context／Harness／Loop）

- 日付: 2026-11-22
- 作者: Avi Chawla @_avichawla（Daily Dose of Data Science）
- カテゴリ: AIエージェント設計
- 元ネタ: https://x.com/_avichawla/status/2124453031559491672

## 要約

X投稿（2026-11-22 19:40、添付は4層を同心円で示すインフォグラフィック）。AIエージェントの設計を「4層のエンジニアリングに包まれた while ループ」と定義する概念解説。各層が前の層を包み込み、中心にモデルが位置する。内側から順に、扱う範囲が「1回の呼び出し」→「1ターン全体」→「呼び出しの周辺コード」→「実行全体」へ広がっていく。

## 4層の内容

### 1. Prompt engineering（1回の呼び出しの入力）

- 入力は役割・指示・例・出力形式で構成される
- 代表的な技法: Chain-of-thought（段階的推論）、Few-shot（例示）、JSONスキーマ／XMLタグによる構造化出力、Self-consistency（複数推論の多数決）

### 2. Context engineering（1ターンでモデルが見える全体）

- 対象はプロンプトだけでなく、クエリ・検索文書・メモリ・過去ターン・ツール出力を含むターン全体
- コンテキストウィンドウは有限なので、「残す価値のあるものだけ」に絞る作業が本体
  - 関連チャンクの検索＋リランク
  - 重要な事実をウィンドウの中盤に置かない
  - 古いターンの要約・破棄、大きな出力のファイル退避

### 3. Harness engineering（モデルの周りのコード）

- ツール定義、ツール呼び出しのパース、失敗時のリトライ、サブエージェントへの作業の振り分けを担う
- 検証器（テスト実行・スキーマ検証など）による結果の採点もここ
- 1回の呼び出しを実システムで動かすための周辺すべてが対象

### 4. Loop engineering（実行全体）

- 外側のループ管理をエージェント自身に任せる層。スケジュールやイベントで起動し、人間のプロンプトなしで多ターンを回す
- 停止判定はエージェントの自己申告ではなく、実シグナルで行う
  - ターン数／トークン数の上限
  - 無進捗の検出
  - 別モデルや決定的テストによる完了チェック
- 注意点: 下位層のコストはループで増幅される。たとえば50Kトークンのツール応答がコンテキストに残り続けると、20ステップのループで数十万トークン規模の読み込みになる
