# Code Execution with MCP：コード実行でトークンを最大98%削減する

- 日付: 2026-11-23

- カテゴリ: AIエージェント実装・MCP

## 要約

X投稿（2026-11-23 23:15、スペイン語）。Anthropic の「Code Execution with MCP（コード実行×MCP）」という手法の解説。全ツール定義を事前にコンテキストへ読み込む従来方式では、ツール数が増えるほどコンテキストが定義だけで埋まってしまう。これに対し、エージェント自身が MCP ツールを呼び出すコードを書き、そのコードをサンドボックス内で実行してフィルタ・結合・集計まで済ませ、処理済みの結果だけをモデルに返す。投稿が引く事例では、ツール定義まわりのトークンが 150,000 → 2,000 に減り、時間・コストで98.7%の削減になったとされる（出典は Anthropic の research 記事とされる）。

## 添付動画のまとめ文書（6要素）

添付動画（24秒）は、第三者 @xwhxrari による非公式のまとめ文書「Harness Notes — Code Execution with MCP」を映したもの。手法は次の6要素で構成される。

| # | 要素 | 要点 |
|---|---|---|
| a | Tools as files | MCP ツールを ./servers 配下にファイルとして置き、必要なファイルだけを読む |
| b | Load on demand | 定義を全件ロードせずオンデマンドに取得する（150K→2K の主因） |
| c | Filter in code | 大量の行データ（例: 10,000行）をコード側で絞り込み、モデルへは数行だけ返す |
| d | Loops in code | ポーリングやリトライなどのループ処理をモデル経由でなくサンドボックス内のコードで回す |
| e | Private by default | 実データはツール間を直接流れ、モデルはトークン化されたプレースホルダだけを見る |
| f | Skills | 動いたコードを ./skills/ に SKILL.md 付きで保存し、次回以降の資産として再利用する |

## 設定プロンプトの骨格

同文書には Claude Code（Fable 5.2）向けの設定プロンプト（20行）が掲載されていた。{MCP SERVERS}・{TASK}・{PRIVATE FIELDS} の3つの差し込み欄を持ち、次の6セクションで上記6要素をそのまま指示する構成。要点のみ記す（全文転記はしない）。

1. Tools as files — ツール定義をファイル化し、必要なものだけ開くよう指示
2. Load on demand — 全定義の事前ロードを禁止し、オンデマンド取得にする
3. Filter in code — フィルタ・結合・集計はサンドボックス内で行い、結果だけ返す
4. Loops in code — ポーリング／リトライはコード側のループで処理する
5. Private by default — 機微な値はプレースホルダ化し、モデルに実データを見せない
6. Skills — 成功したコードは SKILL.md 付きで保存し再利用する
